JavaScript Map vs WeakMap

Understand how WeakMap works, when to use it, and how it differs from Map.

What is WeakMap?

WeakMap stores key-value pairs where keys must be objects. If a key object has no other references in your program, JavaScript can garbage-collect it, and its WeakMap entry can disappear automatically.

How WeakMap Works (Step by Step)

  • Create a key object, then attach hidden data with set().
  • Read with get(), verify with has().
  • Remove explicitly with delete() if needed.
  • No iteration and no size, because keys are weakly held and can disappear at any time.

Example 1: Basic WeakMap Methods


const wm = new WeakMap();
const user = { id: 101, name: "Asha" };

wm.set(user, { role: "Admin" });
const role = wm.get(user).role; // Admin
const hasUser = wm.has(user);   // true
wm.delete(user);

Example 2: Private Data Pattern


const privateData = new WeakMap();

class Account {
  constructor(owner, balance) {
    privateData.set(this, { owner, balance });
  }

  getSummary() {
    const data = privateData.get(this);
    return `${data.owner} has ${data.balance}`;
  }
}

Example 3: Map vs WeakMap Key Rules


const map = new Map();
map.set("token", "abc123"); // valid

const weak = new WeakMap();
weak.set({ id: 1 }, "ok");   // valid
weak.set("token", "abc123"); // TypeError (primitive key)

When to Use Which?

  • Use Map for iterable, countable, general key-value data.
  • Use WeakMap for object-associated metadata or private state that should not keep objects alive.
